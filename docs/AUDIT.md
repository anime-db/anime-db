## 1. Что это за проект

**Anime DB** — настольное приложение для каталогизации домашней коллекции аниме.
Технически это **проект на Symfony 2.7 / PHP ≥ 5.4**, который запускается как
**локальный веб-сервер** (встроенный сервер PHP, `php -S`) на порту **56780** и
хранит данные в **SQLite**. Пользователь работает с приложением через браузер
(`http://localhost:56780/`).

Данный репозиторий — это **«скелет» (project skeleton) + ядровой бандл**
`AnimeDb\Bundle\AnimeDbBundle`. Вся прикладная логика (каталог, фильтры-источники
данных) подключается как отдельные Composer-пакеты `anime-db/*`. Ядро отвечает не
за бизнес-логику, а за **инфраструктуру жизненного цикла**: установку/обновление/
удаление плагинов, самообновление приложения, доставку отложенных событий,
запуск миграций и автонастройку конфигурации Symfony.

Подробнее об устройстве — в [PROJECT.md](PROJECT.md) и [TECHNICAL.md](TECHNICAL.md).

типу (баг/безопасность) и серьёзности.

## 4. Ключевые выводы

### 4.1. Сильные стороны

- **Элегантный жизненный цикл на хуках Composer.** Установка плагина автоматически
  регистрирует бандл в ядре, подключает его routing/config и прогоняет миграции —
  без ручного редактирования файлов. См. [TECHNICAL.md](TECHNICAL.md#жизненный-цикл-composer).
- **Развязка времени Composer и времени выполнения** через механизм отложенных
  событий (сериализация на диск + `animedb:deliver-events`).
- **Хорошая тестовая дисциплина** — почти каждый класс имеет парный тест.
- **Аккуратные манипуляторы файлов** (YAML/JSON/PHP/INI) с единым интерфейсом.

### 4.2. Главные риски (детали — [BUGS.md](BUGS.md), меры — [RECOMMENDATIONS.md](RECOMMENDATIONS.md))

| #  | Риск                                                                                                                            | Серьёзность                     |
|----|---------------------------------------------------------------------------------------------------------------------------------|---------------------------------|
| S1 | Самообновление качает zip и перезаписывает файлы приложения **без проверки подписи/контрольной суммы**                          | 🔴 Критично                     |
| S2 | Монитор (Windows-бинарь) скачивается по **plain HTTP** (`http://anime-db.org/...`) — MITM → подмена исполняемого файла          | 🔴 Критично                     |
| S3 | Симфониевый `secret` генерируется через `rand()` — **криптографически непригоден**                                              | 🟠 Высоко                       |
| S4 | `app_dev.php` запускается без ограничения по IP (`umask(0000)`), профайлер доступен по всей локальной сети                      | 🟠 Высоко                       |
| B1 | `UpdateItself::onAppDownloadedMergeAppSource` теряет разделитель пути и структуру каталогов при копировании — файлы «слипаются» | 🔴 Критично (ломает обновление) |
| B2 | `GitHub::getLastRelease` не обрабатывает ошибки API (rate-limit/4xx) — падение/неверное поведение                               | 🟠 Средне                       |
| B3 | Самообновление жёстко ограничено `< 1.0.0` — **не может обновиться до 2.x**                                                     | 🟠 Средне                       |
| B4 | IPv6-проверка локальной сети ловит только `fc00::`, но не `fd00::/8` (типичные ULA)                                             | 🟡 Низко                        |

### 4.3. Долговые/стратегические наблюдения

- **EOL-стек.** Symfony 2.7 (EOL май 2019) и PHP 5.4 (EOL 2015). Любая
  установка зависимостей сегодня проблематична; `minimum-stability: dev`.
- **Встроенный сервер PHP как продакшен-сервер.** `php -S` официально не
  предназначен для продакшена (однопоточный, без харднинга). Для домашнего
  использования приемлемо, но это архитектурное ограничение.
- **Рассинхрон версий.** Ветка `2.x`, а `composer.json` → `0.3.29`,
  `CHANGELOG.md` остановлен на `0.3.16` (2015), `branch-alias` → `0.3.x-dev`.

## 6. Приоритетный план действий (TL;DR)

1. **Исправить B1** — без этого самообновление повреждает установку. 🔴
2. **Закрыть S1/S2** — перейти на HTTPS для монитора, добавить проверку
   контрольной суммы/подписи дистрибутива. 🔴
3. **Заменить `rand()` на `random_int()`** в `SecretKey` (S3). 🟠
4. **Убрать `umask(0000)` и закрыть `app_dev.php`** по IP (S4). 🟠
5. **Согласовать версии** или зафиксировать решение, что `2.x` — отдельная линия.
6. Среднесрочно — план миграции стека (см. [RECOMMENDATIONS.md](RECOMMENDATIONS.md)).
