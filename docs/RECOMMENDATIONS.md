# Anime DB — рекомендации

> Меры по повышению сопровождаемости и безопасности. Конкретные дефекты —
> [BUGS.md](BUGS.md), механика — [TECHNICAL.md](TECHNICAL.md), сводка —
> [AUDIT.md](AUDIT.md).

## 1. Безопасность (приоритет)

### 1.1. Цепочка обновления — главный риск

Самообновление — самая опасная подсистема: оно скачивает код и исполняемые файлы
и перезаписывает приложение. Минимальный набор мер:

- ✅ **HTTPS везде.** Заменить `anime_db.monitor` на `https://…` ([S2](BUGS.md#s2)).
- ✅ **Проверка целостности.** Публиковать SHA-256/подпись релиза и монитора;
  проверять перед распаковкой/перезаписью ([S1](BUGS.md#s1)).
- ✅ **Пинить хост API** `https://api.github.com`, запретить переопределение из
  недоверенных источников.
- ✅ **Транзакционность апдейта.** Сейчас `rewriting()` сначала `rm -rf src/ app/`,
  потом `mirror`. При сбое между шагами приложение остаётся «битым». Делать
  обновление во временном каталоге и атомарно переключать, с откатом из бэкапа.

### 1.2. Секреты и сессии

- ✅ Заменить `rand()` → `random_int()`/`random_compat` ([S3](BUGS.md#s3)).
- ✅ Не хранить `database_user: root` в `parameters.yml.dist` (для SQLite он не
  нужен — ввести в заблуждение легко).

### 1.3. Поверхность атаки HTTP

- ✅ Не поставлять `app_dev.php` в релизе или закрыть его IP-guard'ом; убрать
  `umask(0000)` ([S4](BUGS.md#s4)).
- ✅ В `StaticFiles` добавить `realpath`-confinement и белый список расширений
  ([B6](BUGS.md#b6)).
- ⚠️ Осознанно зафиксировать, что приложение биндится на `0.0.0.0` и пускает всю
  приватную сеть. Если задумано «только этот ПК» — биндить `127.0.0.1` по
  умолчанию, а сетевой доступ делать опцией.

### 1.4. Десериализация

- ✅ Заменить `unserialize()` отложенных событий на безопасный формат или
  ограничить `allowed_classes` ([S5](BUGS.md#s5)).

## 2. Корректность и надёжность

- ✅ Исправить копирование исходников при апдейте ([B1](BUGS.md#b1)) — блокер.
- ✅ Обработка ошибок GitHub API + User-Agent + тайм-ауты ([B2](BUGS.md#b2)).
- ✅ Команды должны возвращать корректные exit-коды ([B7](BUGS.md#b7)).
- ✅ Поправить IPv6 ULA-проверку ([B4](BUGS.md#b4)).
- ✅ Защититься от `md5_file()` по несуществующим файлам ([B5](BUGS.md#b5)).

## 3. Версионирование и релизы

Сейчас всё рассинхронизировано: ветка `2.x`, `composer.json: 0.3.29`,
`CHANGELOG.md` заморожен на `0.3.16` (2015), `branch-alias: 0.3.x-dev`,
самообновление ограничено `<1.0.0`.

Рекомендации:

- Принять решение: `2.x` — это продолжение или отдельная линия? Зафиксировать в
  README/CONTRIBUTING.
- Привести `composer.json.version`, `branch-alias` и верхнюю границу апдейтера
  ([B3](BUGS.md#b3)) к этому решению.
- Возобновить `CHANGELOG.md` (или перейти на GitHub Releases как единый источник).

## 4. Актуализация стека (стратегически)

| Зависимость         | Сейчас  | Статус                                |
|---------------------|---------|---------------------------------------|
| PHP                 | ≥ 5.4   | EOL (2015)                            |
| Symfony             | ~2.7    | EOL (2019)                            |
| Doctrine ORM        | ~2.4.8  | сильно устарела                       |
| Guzzle              | 3.9     | EOL, заменён на guzzlehttp/guzzle 6/7 |
| PHPUnit             | ^4.8    | EOL                                   |
| `minimum-stability` | `dev`   | рискованно для воспроизводимости      |

Сегодня `composer install` на современной системе почти наверняка не пройдёт без
старого PHP. Варианты:

1. **Заморозить как есть** + Docker-образ с PHP 5.6/7.1 для воспроизводимости
   (минимум усилий, «музейный» режим).
2. **Поэтапная миграция**: Guzzle → guzzlehttp, PHPUnit → 9, затем Symfony 2.7 →
   3.4 LTS → 4.4 → 5.x, PHP → 7.4/8.x. Большой объём, но снимает EOL-риски.

Рекомендация: как минимум №1 для воспроизводимости сборки + дорожная карта №2.

## 5. Сопровождаемость

- **Разнести ответственность апдейтера.** `UpdateItself` — «бог-класс» на 6 шагов
  слияния с захардкоженными путями/именами (`AnimeDB_Run.vbs`, `config.ini`,
  `bin/service`). Вынести стратегии слияния в отдельные классы с тестами на каждый
  шаг переноса.
- **Конфигурируемые пути и URL.** Параметры монитора/API — в `parameters.yml`,
  без литералов в коде.
- **`ManipulatorInterface` — пустой маркер.** Если интерфейс не описывает контракт,
  он не помогает. Либо ввести реальные методы (`get/set`/`read/write`), либо убрать.
- **Документация на русском в составе репозитория** уже частично есть (`CLAUDE.md`).
  Поддерживать `docs/` (эти файлы) в актуальном состоянии.
- **CI.** Travis устарел/выключен; перевести на GitHub Actions с матрицей PHP,
  Composer-кешем и запуском PHPUnit.

## 6. Тестирование

- Покрытие хорошее, но **нет тестов на `UpdateCommand`-сценарий целиком** и на
  именно ту ветку `onAppDownloadedMergeAppSource`, где живёт [B1](BUGS.md#b1).
  Добавить интеграционный тест переноса данных при апдейте — он бы поймал баг.
- Добавить тесты на обработку ошибок GitHub API.

## 7. Быстрые победы (low-effort, high-value)

1. `random_int` в `SecretKey` — 1 строка.
2. `http` → `https` для монитора — 1 строка.
3. Убрать `umask(0000)` из `app_dev.php`.
4. Починить разделитель пути в `onAppDownloadedMergeAppSource` ([B1](BUGS.md#b1)).
5. IPv6 `fc00::/7` вместо `fc00::`.
